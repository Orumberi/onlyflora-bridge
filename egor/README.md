# Егор Григорьевич S — первая тестовая версия

Состояние: исходный код для тестирования, **не установлен в Only Test**.
В комплект входит новая главная для клона: чистая шапка, первый экран, реальные
категории и реальные товарные карточки, а также правая панель помощника. Скрипт
берёт ссылки и изображения из уже отрисованной витрины; фиктивные товары не создаёт.
Интерфейс: фото JPEG/PNG/WebP или текст → проверка строк → предложения SKU → CSV.
PDF и Excel в этой версии не реализованы. Фотографии не сжимаются и не сохраняются
сервером приложения; для распознавания передаются OpenAI с `store:false`.
Это не обещание нулевого хранения у провайдера: действуют настройки его аккаунта.

## Почему такой вариант

OnlyFlora размещён в Webasyst Cloud. Произвольный приватный PHP-плагин туда нельзя
просто загрузить: облако устанавливает проверенные продукты через Installer.
Поэтому интерфейс подключается только в клоне `onlytest`, а `/egor/` работает
в существующем Node-приложении Bridge. MCP-инструменты администрирования не
предоставляются посетителю. Сервер Егора вызывает только два GET-метода Webasyst.

## Что уже работает в коде

- Разбор текстовых строк и интерфейс проверки; фото через Responses API.
- Размер, контейнер, питомник, цена и остаток берутся из **одного SKU**.
- Общие `features` мастер-карточки не подменяют характеристики предложения.
- Нет молчаливых замен сортов, размеров или контейнеров.
- Количество можно собрать из нескольких предложений. Повторяющиеся строки
  используют один общий остаток, не удваивая его.
- Остаток `null` означает неограниченный учёт в Shop-Script, но не доказательство
  наличия: такое предложение не включается автоматически.
- Скрытые товары, отключённые SKU, предложения без цены не подбираются.
- Цена считается в копейках. В сумму не входит доставка.
- Две стратегии: цена; эвристическое сокращение числа питомников.
- Ограниченный поиск с постраничной загрузкой и явным признаком неполноты.
- В браузер не передаются закупочные цены, контактные ID или токены Webasyst.
- Фото/списки/секреты не журналируются кодом приложения; сервер не хранит подборы.

## Границы первой версии

Автоподбор поддерживает оба обнаруженных формата master-SKU:
`60–80 см, C3, Питомник` и `Питомник · 110 см · WRB`.
Неполные или неоднозначные варианты не трактуются как точные предложения.
Поддерживаются штучные растения с шагом/минимумом заказа 1, валюта RUB.
Набор синонимов намеренно ограничен и прозрачен. Опечатки и новые синонимы
исправляются человеком на шаге проверки; модель не назначает SKU сама.
Режим «меньше поставщиков» — жадный алгоритм, а не доказанный глобальный оптимум.
Фото и настоящий API-токен не доступны в локальном окружении: реальный сквозной
тест распознавания и онлайн-подбора ещё необходим перед открытием клиентам.

## Установка в существующий Bridge

1. Внести переменные из `egor/.env.example` в секреты текущего хостинга. Для
   каталога нужен отдельный OAuth-токен сотрудника с правами только чтения.
   Не извлекать и не переносить токен соединения ChatGPT для публичного сервиса.
2. Установить `EGOR_ENABLED=true`, задать preview-код не короче 32 символов.
3. Развернуть эту ветку. Команды существующего Bridge `npm ci`, `npm start`
   сохраняются. До настройки сервис закрыт и не вызывает внешние API.
4. Открыть `/egor/`, ввести preview-код и проверить текстовый список. Затем
   добавить ключ и модель с поддержкой vision/Structured Outputs, проверить фото.
5. Считать актуальный `index.html` **родительской темы приложения Сайт onlytest**.
   Не использовать старую локальную копию вместо свежего шаблона.
6. Подготовить отдельную копию:

   `node egor/prepare-onlytest.mjs index-current.html index-with-egor.html https://DEPLOYED-BRIDGE-HOST`

   Скрипт добавляет два тега загрузки перед `</body>` под проверкой `$wa_theme_id`:
   обратимый слой новой главной и панель Егора. Оба скрипта дополнительно проверяют
   подключённые ресурсы `/themes/onlytest/` и ничего не меняют на других темах.
   Шаблон сохраняется новым файлом; существующий не перезаписывается.
7. Загрузить подготовленную копию только в `Сайт → onlytest → index.html`.
   Сравнить разницу: только блок `onlyflora-onlytest-modern` из двух строк загрузки.
   Открыть предпросмотр. Исходная разметка ProStore не удаляется: на главной клона
   она лишь скрывается после успешной загрузки нового слоя.
8. Проверить: фото → редактирование → подбор по свежим SKU, мобильный экран,
   дубли строк, дефицит, замены, ошибки сети и CSV. На основном `prostore`
   виджет отсутствует. Кнопки не заменяют cookie-баннер.

Для отката убрать только блок `onlyflora-onlytest-modern` вместе со следующей
строкой `onlyflora-egor-widget` и выключить `EGOR_ENABLED`.
Preview-код хранится только в памяти вкладки; после перезагрузки вводится снова.
Это закрытый пилот. Перед публичным запуском требуется отдельное решение по
ограничению расходов/злоупотреблений, жизненному циклу токенов и полной поддержке
форматов SKU. CORS и проверка темы не используются вместо авторизации.

## Проверки

`npm ci && node --test egor/test/*.test.js`

Реальные снимки товара 18544 и восьми карточек по запросу «Смарагд» получены
через Bridge 21.09.2026. В фикстурах оставлены только публичные свойства предложений.
Это фикстура теста алгоритма, не источник текущих цен для клиентов.
Остальные фикстуры тестов синтетические и нигде не отдаются на витрину.
